# 钟乳石洞穴微环境巡测

## 启动

```bash
npm install
npm start
```

默认地址：http://localhost:3912

数据保存在`data/db.json`，后续可以继续增量迭代。

## 测试

```bash
npm test
```

覆盖：旧版单条登记与状态流转、批次草稿暂存与恢复补交、重复提交幂等、双终端冲突判定、自动待复核规则、暂停开放样点降级边界、批次完成边界、审计留痕。

## 巡测批次（按路线一次录入多个样点）

- 「巡测批次」页按路线加载全部样点，一次录入多条读数；提交后为每个样点生成一条巡测记录。
- **草稿暂存**：班次结束前可暂存草稿（按批次号幂等 upsert），断网时草稿自动保存在本地，恢复连接后可补交；已提交的批次不允许被草稿覆盖。
- **重复提交**：同一终端对同一批次号重复提交，返回已有结果，不生成重复记录。
- **冲突判定**：两个终端提交同一批次号时，先到的生效，另一终端收到 409 冲突提示，只保留一份有效结果。
- **自动待复核**：任一读数越过样点基准（温度或 CO2 高于基准、湿度低于基准）且记录了干扰痕迹，该条记录自动进入「异常待复查」，批次进入「待复核」。
- **提交边界**：批次只接受所选路线下的样点，同一样点每批只能保有一份读数；跨路线或重复样点的提交整体拒绝，不写入任何批次和巡测数据，返回 `code: BATCH_VALIDATION` 及逐条 `details`（`ROUTE_MISMATCH` / `DUPLICATE_SITE` 等），页面内联显示错误原因。
- **复核边界**：复核通过前，暂停开放的样点不能降级（重点保护/常规观察被拒绝），批次也不能完成；复核通过后放行。
- **审计留痕**：每次提交和状态变化都记录处置人、时间和原因（页面右上角设置处置人，状态操作可填写原因）。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `PUT` | `/api/batches/draft/:batchKey` | 暂存/更新草稿（幂等） |
| `POST` | `/api/batches/submit` | 提交批次（幂等 + 冲突判定），body 含 `batchKey`、`terminalId`、`route`、`shiftDate`、`surveyor`、`readings[]` |
| `POST` | `/api/action/batch-complete/:id` | 完成批次（有待复核记录时拒绝） |
| `GET/POST/PATCH/DELETE` | `/api/...` | 旧版通用接口（批次集合对其关闭，返回 405） |
